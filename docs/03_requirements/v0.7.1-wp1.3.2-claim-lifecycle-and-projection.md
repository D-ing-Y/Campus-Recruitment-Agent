# v0.7.1 WP1.3.2 Claim 生命周期与增量投影需求

状态：Implemented / Accepted  
日期：2026-08-02

## 1. 问题

ResumeEvidence v2 重新生成 Candidate 时，Projector 读取候选人的全部 active Claim，导致旧简历
解析 Claim、当前 Resume Claim、长期对话和面试反馈混为同一事实集合。代码/Prompt 升级只是暴露
问题；长期使用同一代码版本也会因新证据持续到达而复现。

## 2. 必需行为

1. Claim 必须记录来源种类、来源对象、生效时间和多前驱 supersede；旧 JSON 继续可读。
2. Candidate 投影必须显式绑定当前 confirmed ResumeEvidenceSnapshot。
3. 旧 Resume 版本和 legacy model Claim 保留审计但不得污染当前画像；human/feedback legacy 保留。
4. conversation、feedback、supplemental document Claim 跨简历版本保留，直到显式 supersede。
5. 同 predicate 的语义等价/精化不得制造冲突；跨来源语义不同必须进入 HITL。
6. 一次用户 correction 只创建一条 successor，并在单事务中 supersede 全部目标 Claim。
7. CandidateSnapshot 必须保存当前 evidence basis，并只引用本次 resolution 选中的 Claim。
8. Provider 失败后 CLI 必须给出真实可执行的 session 恢复与 Candidate 重试路径。

## 3. 最小范围

- 复用 SQLite JSON payload、EvidenceClaim、CandidateProfileProjector 和 ProfileSnapshot；
- 不实现 valid_to 区间查询、自动过期、图数据库、通用规则引擎或后台生命周期任务；
- disputed 是投影派生状态，不扩展持久化 ClaimStatus；
- WP2 领域模型不修改，只用新 CandidateSnapshot 重验 typed input。

## 4. 验收

- Resume v1 → v2 后 stale Resume Claim projection count 为 0；
- legacy model Claim projection count 为 0，历史 payload 不变；
- SQL 元数据与毕业时间精度不产生伪冲突；
- 跨来源不同能力等级仍触发 HITL；
- 多前驱 correction 原子、幂等且只产生一个 successor；
- 当前 Resume trace rate 为 1.0；
- 真实 Candidate 与 WP2 typed handoff 重验完成后才恢复 WP1/WP2 Passed。
