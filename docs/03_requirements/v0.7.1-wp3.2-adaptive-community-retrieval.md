## 1. 目标

用受控外部搜索发现公开牛客详情 URL，以 Crawl4AI 批量抓取详情正文；小红书继续使用
MediaCrawler localhost REST。社区检索在确定性安全、证据、预算和 scope 门禁内，由 LLM 判断
关键词缺口、来源优先级与信息充分性。

```text
controlled query planning
  -> Brave Search URL discovery
  -> allowlisted Nowcoder detail URLs
  -> Crawl4AI batch detail fetch
  -> Raw Artifact
  -> deterministic body extraction
  -> typed community extraction
  -> content clustering
  -> bounded source/sufficiency decision
  -> Demand assessment / Reputation projection
```

## 2. 功能要求

### FR-01 来源边界

- `nowcoder_experience` 的 search 只能调用 Brave Search API，不得请求牛客 `/search`。
- Brave snippet 只用于候选发现，不得生成 Segment、Claim 或 Profile。
- `xiaohongshu_experience` 继续调用 MediaCrawler localhost REST；Graph 不经过 MediaCrawler MCP。
- Source ID 保持不变；招聘和官网来源不受本工作包影响。

### FR-02 详情抓取

- 新增 `source.fetch_community_details`，一次接收有界 `SourceDetailRequest[]`。
- 牛客详情使用 Crawl4AI `AsyncWebCrawler.arun_many()`，默认并发 2；不得启用 Crawl4AI LLM、
  Docker Server、MCP、代理、隐身或验证码绕过。
- 请求 URL 与最终 URL 均须通过 `www.nowcoder.com` 域名和详情路径 allowlist。
- robots 禁止、限流、登录墙、风控、DOM 漂移和依赖缺失必须使用已有结构化错误状态。

### FR-03 Raw-before-parse

- Brave JSON、Crawl4AI rendered HTML/cleaned HTML/Markdown/metadata、MediaCrawler JSON 均先归档。
- 成功的 `experience_search`/`experience_post` 必须关联 Raw Artifact 和 content hash。
- 牛客主帖正文由版本化站点 Profile 的有序 CSS/XPath selector 提取；找不到唯一正文时返回
  `source_changed`，不得回退到整页文本作为证据。

### FR-04 自适应决策

- 每次 run 分别为 `interview_experience`、`employment_experience` 建立来源评估。
- 校准阶段每来源每用途最多采样 2 篇有效详情；确定性指标包括详情有效率、scope 命中、Segment
  产出、独立簇产出、重复率、失败率、延迟和 search/detail 次数。
- LLM 只能输出来源排序、缺失主题、关键词建议和 `sufficient|insufficient`；代码把来源排序映射为
  70/30 预算，单来源不可用时映射为 100/0。
- 公司只能使用法定名或版本化 verified alias；角色词只能来自当前 exact role、岗位族展示名和受控
  同义词；代码始终添加目标域名并拒绝新来源、新公司、新岗位族和预算修改。
- 保留每来源每用途最多三轮和全局 Tool/Query/Document/LLM 预算。

### FR-05 内容独立性与停止

- 精确去重依次使用 canonical URL、平台 post ID 和规范正文 hash。
- 近重复使用规范化中文 5 字符 shingle Jaccard；`>=0.85` 进入同一簇。
- LLM 可以基于有界 Segment 摘要提出 semantic merge，但必须引用已有 segment ID；代码只允许 merge，
  不允许拆开确定性重复簇。
- 面经和风评必须分别达到 3 个最终独立 `CommunityContentCluster`，LLM 才能判定 sufficient。
- 预算耗尽、来源阻断或没有有效新查询时输出 `budget_exhausted|blocked|insufficient`，不得伪造完成。

### FR-06 上下文与审计

- 逐帖分类保持独立 LLM 调用；聚合评估器只接收有界 metadata、limited summary、quote、segment ID
  和统计指标，不接收帖子全集。
- 抽取、来源评估和查询决策全部计入 `max_llm_calls`；Graph 必须在调用前检查剩余预算。
- 所有 LLM 决策保存 `CommunitySearchDecisionReceipt`；无效 schema、越权建议或引用不存在时拒绝并使用
  确定性安全回退。

## 3. 非目标

- 不把搜索引擎摘要、LLM 常识或整页导航文本作为岗位画像证据。
- 不新增 Firecrawl、Scrapy、Trafilatura、向量库或搜索 SDK。
- 不删除通用 `MCPToolCatalog`、招聘/官网 SourceAdapter 或 MediaCrawler REST Client。
- 不绕过 robots、登录、验证码、风控或访问限制。

## 4. 完成条件

- 文档、契约、代码、单元/集成测试和 Eval report 均完成。
- 默认离线测试证明没有牛客 `/search` 请求、搜索摘要投影、越权 LLM 决策或敏感信息泄漏。
- Opt-in live 分别记录 Brave、Crawl4AI、MediaCrawler 的真实成功或真实阻断结果。
- 面经/风评各 3 个独立簇只作为完整 live acceptance；未满足时保持 partial。
