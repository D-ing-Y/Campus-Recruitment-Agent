## 1. 当前问题

v0.6 已有 CareerIntent schema、matching 消费和 revision，但没有首次生产入口。调用方只能手工构造
snapshot，原始用户意图没有 Evidence Artifact/Fragment，扁平 discovery 字段与 constraints 可能双写
漂移，也没有 CLI confirmation、独立 checkpoint、SearchScope 投影记录和发往 WP3 的 typed handoff。

## 2. 目标

实现以下纵向闭环：

```text
raw user intent
  → immutable EvidenceArtifact / EvidenceFragment
  → DeepSeek non-thinking Tool Calling candidate
  → Pydantic + intent-domain Validator
  → Human confirmation/revision
  → immutable CareerIntent ProfileSnapshot
  → deterministic SearchScope projection
  → role_research_required Handoff
  → CLI/inspect/Eval
```

## 3. 必须满足的业务语义

- `Agent 开发` 保留为原始 role query，并可由确定性 alias policy 投影为
  `ai_agent_engineering` family；LLM 不创建任意 family ID。
- `成都，工作地点必须成都` 必须成为 confirmed hard location constraint。
- 明示 `2027 年毕业` 可成为 confirmed graduation year constraint。
- 仅说 `校招` 时必须保留 `campus_unspecified`，不得擅自推断秋招或春招；持久化前要求用户确认
  `autumn_campus | spring_campus | unknown`。
- `优先大型企业以及互联网科技公司` 必须是 negotiable company-type preference，不得升级为 hard。
- CareerIntent 不写 Candidate Claim；Candidate 能力也不得进入 SearchScope。
- 只有 confirmed CareerIntent 可以投影 SearchScope 和生成 WP3 handoff。

## 4. 功能要求

1. `intent create` 接收非空原始文本和已有 Candidate session。
2. 原始文本先归档，再允许调用模型；模型失败仍保留 raw artifact 并生成可诊断失败 run。
3. Structured output 使用 `CareerIntentCandidate`，DeepSeek 继续走非思考 Tool Calling。
4. candidate 的 fragment refs、枚举、关键 hard/preference 边界由领域 Validator 检查。
5. 初次 create 必须 interrupt 等待用户确认，不允许模型直接发布 snapshot。
6. `intent resume --action revise` 接收 allowlisted patch；`confirm` 仅在无 unresolved field 时成功。
7. response ID 幂等；相同 ID 不同 payload 失败；重复确认不重复创建 snapshot/scope/handoff。
8. snapshot、SearchScope 和 handoff 都校验 owner、predecessor 和 schema。
9. CLI 提供 create/resume/show；JSON stdout 不输出完整 raw intent 或 secret。
10. run artifact 包含 node event、LLM receipt、artifact index、state、handoff 和 terminal manifest。

## 5. 非目标

- 不在 WP2 调用招聘平台或企业官网；这些属于 WP3。
- 不实现 Parent Graph、自动递归消费 handoff 或 Web UI。
- 不把所有自由文本偏好强行映射为搜索条件；不确定项保留 `other/unknown`。
- 不让 Tool Calling/Pydantic 代替领域分类、用户确认和证据追踪。

## 6. 放行条件

- E0-E3 fixtures、CLI 跨进程 resume、幂等/失败注入和全量回归通过。
- active DeepSeek 对真实意图完成一次 E4 Tool Calling smoke，Pydantic 与领域 Validator 通过。
- 关键边界集 hard/preference 与 SearchScope 投影准确率 100%。
- 真实 run 的下一步为 `role.research`，但不得声称 WP3 已实现。
