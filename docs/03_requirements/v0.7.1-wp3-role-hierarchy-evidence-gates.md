# v0.7.1 WP3 岗位层级与详情证据门禁修正

状态：Implemented / Offline Passed（WP3 authenticated-live 未开始）
日期：2026-08-03
关联 RFC：`docs/04_rfc/0014-role-hierarchy-and-detail-evidence-gates.md`
关联 ADR：`docs/05_adr/0014-preserve-role-instance-family-and-gate-detail-evidence.md`
关联支持矩阵：`docs/06_contracts/v0.7.1-wp3-live-source-support-matrix.md`

## 1. 背景与问题

v0.5 已实现 `JobInstanceRoleProfile → RoleFamilyProfile` 两级岗位画像，但在接入
v0.7.1 正式 CLI Workflow 前存在四个会污染岗位族统计或具体岗位回答的问题：

1. CareerIntent 可包含多个目标方向，但当前只生成一个 SearchScope，并把全部查询词绑定到
   第一个 `target_role_family`；后端、算法、AI 应用等方向可能被混入同一统计分母。
2. NormalizedJobPosting 缺失来源岗位族时会直接继承 SearchScope 的 family；搜索噪声因而可能
   未经归属校验进入岗位族画像。
3. search page/card 与 job detail 虽有不同 document kind，但具体岗位投影没有强制详情证据门禁；
   搜索摘要可能被误当作完整 JD。
4. ExperienceEvidenceRecord 虽有 scope_level，但挂载到具体岗位主要依赖公司和标题字符串；同名
   岗位、标题变体和未知 scope 可能误挂或漏挂。

## 2. 目标

- 一个 CareerIntent 按 canonical role family 确定性拆成 1..N 个独立 SearchScope。
- 每个招聘岗位在进入 JobPostingCluster 和岗位族统计前产生可审计 RoleFamilyMembership。
- 只有具有真实 detail Raw Artifact 的岗位 cluster 才能生成 JobInstanceRoleProfile。
- 每条经验记录先产生 ExperienceScopeLink，再按 confirmed scope 投影 HiringSignal。
- 保持现有 EvidenceArtifact、Claim、JobIdentityLink、FieldResolution 和两级 RoleProfile；不引入
  图数据库、向量聚类或新的通用规则引擎。

## 3. 功能要求

### FR-01 多 SearchScope 投影

- CareerIntent 保存逐项 `RoleTargetBinding(target_role, role_family)`，不得只保存两个失去对应关系的列表。
- 同一 family 的多个 target role 合并为一个 SearchScope；不同 family 必须产生不同 SearchScope。
- SearchScope 的地点、毕业年份、招聘类型和确认后的 hard constraints 保持一致，查询词只包含该
  family 的 target role。
- 每个 SearchScope 产生独立 `role_research_required` Handoff；旧单 Scope 字段继续只读兼容。
- 旧 CareerIntent 缺失 bindings 时，以每个 target role 重新执行确定性 family mapping；不得把全部
  target role 静默绑定到第一个 family。

### FR-02 RoleFamilyMembership 门禁

- 每个 recruitment NormalizedJobPosting 必须产生一个 membership receipt，包含 scope、目标 family、
  inferred primary family、secondary tags、status、confidence、reason codes 和 Fragment 引用。
- `accepted` 才能进入 JobPostingCluster 和 RoleFamilyProfile 分母；`ambiguous/rejected` 保留记录但不投影。
- family 推断只读取岗位标题和受控别名规则；JD 技术栈可作为 secondary tag，不得因为出现 Python
  就把后端岗位自动改成算法岗位。
- Normalizer 不再用 SearchScope family 覆盖缺失的岗位族。
- Membership 策略和别名版本必须进入 receipt。

### FR-03 Detail Evidence Gate

- `search_page`、`official_search` 和 `experience_search` 只能发现候选 URL，不能满足详情门禁。
- 岗位详情只接受 `job_detail`、`employer_job_detail` 或 `official_job_detail` 的成功 SourceDocument，
  且必须具有 Raw Artifact/hash。
- 每个 cluster 产生 `RoleDetailEvidenceReceipt`；只有 `eligible` cluster 可以提取 Role Claim、执行
  FieldResolution 和生成 JobInstanceRoleProfile。
- 搜索页中嵌入的卡片或 initial state 可以作为 discovery candidate，但不得冒充 detail Artifact。
- 无详情证据时保留 candidate、membership 和门禁拒绝原因，Candidate Claim 数量不受影响，且不得
  生成半成品岗位画像。

### FR-04 ExperienceScopeLink

- 每条去重 ExperienceEvidenceRecord 必须产生显式 scope link。
- `role_family` scope 绑定当前 family；`company_only` 绑定公司；`company_role` 绑定公司和岗位族；
  `job_instance` 必须唯一匹配一个 JobPostingCluster。
- 多个候选或证据不足时为 `ambiguous`，不得挂载到任一具体岗位。
- JobInstanceRoleProfile 只消费与自身 cluster/company/family 相容的 confirmed link；
  RoleFamilyProfile 可聚合 confirmed family/company/job 信号并继续保留原始 scope。
- community evidence 仍禁止确认岗位存在、申请入口、资格或 hard requirement。

## 4. Workflow 修正

```text
CareerIntent
  → project_role_target_bindings
  → project_search_scopes
  → emit one handoff per scope

SearchScope
  → discovery search raw
  → normalize candidates
  → classify_role_family_membership
  → deduplicate accepted jobs
  → experience search/detail normalize + dedup
  → link_experience_scopes
  → official verification/detail raw
  → assess_role_detail_evidence
  → role claims / field resolution
  → JobInstanceRoleProfile
  → RoleFamilyProfile
```

## 5. 非目标

- 本补丁不实现多层 Role Taxonomy DAG；`backend/algorithm/ai_application` 等 canonical family
  仍是 RoleProfileGraph 的聚合边界。
- 不实现语义向量聚类、Hybrid RAG 或自然语言岗位问答；只保证后续可按 snapshot/Claim/Fragment 检索。
- 不把用户心仪公司或岗位优先级写入客观 RoleProfile；该优先级属于 WP4 TargetDecision。
- 不修改 WP5 的准备排序；“通用基础 → 具体 JD”由 WP4/WP5 后续 contract 消费 RoleFamilyProfile。

## 6. 验收标准

- 三个 target role、两个 family 生成两个 SearchScope 和两个 pending handoff。
- 任一 scope 的 RoleFamilyProfile 不包含其他 family 的 accepted job。
- 只有 search_page 的 cluster 产生 `detail_evidence_missing` 且岗位画像数量为 0。
- search_page + job_detail 的同一岗位只计一个 cluster，并可生成一个 JobInstanceRoleProfile。
- ambiguous experience link 不进入任何 JobInstanceRoleProfile。
- confirmed job/company/family link 分别只进入允许的画像范围。
- 所有 membership、detail receipt 和 scope link 可追溯到 Fragment/Artifact。
- v0.1-WP2 与 v0.5 Role fixture 回归通过。
