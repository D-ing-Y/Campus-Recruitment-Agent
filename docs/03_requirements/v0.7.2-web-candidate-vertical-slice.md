# v0.7.2 Web Candidate Vertical Slice 需求

状态：Implemented / Offline Accepted
日期：2026-08-13

## 1. 目标

在不修改现有 Candidate、ResumeEvidence、Session、Evidence 或 Runtime 业务实现的前提下，新增一个本地单用户 Web 产品入口，完成以下真实纵向闭环：

```text
创建本地任务
  → 上传文本型 PDF 简历
  → 查看结构化解析进度
  → 按八区块审核、纠正或删除记录
  → 发布 confirmed ResumeEvidenceSnapshot
  → 构建 CandidateProfile
  → 回答定向问题或补充项目材料
  → 查看画像、证据边界和版本变化
```

Web 是现有 Application Service 的新适配器，不建立 Parent Graph，也不复制 Graph、Validator、Projection 或 Repository 业务逻辑。

## 2. 用户范围

- 第一版面向本机产品演示、个人使用和受控的身边用户测试准备。
- 固定本地用户身份，不实现注册、登录、邀请、RBAC 或公开互联网部署。
- 不把本地单用户模式描述为多用户安全边界或生产可用服务。

## 3. 功能要求

### FR-01 产品框架

- 响应式 Web 应用，桌面端优先且可在手机宽度使用。
- 白色底板、橙色高亮、细边框、轻阴影和清晰的信息层级。
- 顶部显示产品身份和本地模式；左侧或顶部显示 Candidate 流程进度。
- 岗位研究、匹配和准备计划可以作为不可操作的后续阶段提示，不伪造结果。

### FR-02 Session

- 用户可以创建或恢复一个本地 Candidate Session。
- Web 只展示 Session 的阶段、当前对象引用、pending request 和 next action。
- Session、Graph checkpoint、Evidence Store 与浏览器状态不得互相替代。

### FR-03 ResumeEvidence

- 上传仅接受现有业务支持的文本型 PDF。
- Web 上传层生成受控临时文件，Application Service 完成归档后立即清理临时文件。
- 审核页面展示当前 section/record、结构化字段、来源页码和有限证据摘录。
- 支持 `confirm | correct | remove | retry | cancel`，并透传 request、draft revision 与 response identity。
- 未完成全部审核前不得显示已发布 ResumeEvidence 或可构建画像。

### FR-04 CandidateProfile

- 只使用当前 Session 中 confirmed ResumeEvidenceSnapshot 构建 CandidateProfile。
- 展示教育、经历、能力、职责边界、冲突、unknown、证据引用和完成原因。
- interrupted 时按现有 `HumanInteractionRequest` 展示问题、允许动作及补充材料要求。
- 支持 `answer | upload | correct | confirm | skip | cancel`；首版 UI 至少完成 answer、upload、skip、cancel。
- 新画像发布后可显示 predecessor/current 的 ProfileVersionDiff。

### FR-05 API 适配

- Web API 直接调用 `RuntimeFactory` 和现有 Application Service，不启动 CLI 子进程。
- API 把领域异常映射为稳定 HTTP 状态与安全错误 envelope。
- API 不新增事实，不修改 Candidate 路由，也不绕过 owner、request、action、CAS 或 idempotency 校验。
- 充分性 evaluator、question planner 和 LLM provider 保持 Runtime 内部依赖；Web 只消费稳定输出契约。

### FR-06 本地安全

- 不从客户端接受服务器绝对路径。
- 上传限制为 PDF/Markdown/TXT/README 的现有业务允许范围；首次简历仅 PDF。
- 上传文件名、正文、PII、Prompt 和 API key 不进入浏览器日志或 Web API 错误。
- 浏览器只保存非权威的当前 session ID；业务状态继续保存在现有 SQLite、BlobStore 与 checkpoint。

## 4. 非目标

- 不修改 `src/campus_job_agent` 中现有业务行为。
- 不切换到 LLM SufficiencyEvaluator，不扩展 Candidate ontology。
- 不实现公开部署、登录、计费、限流、邮件、通知或团队协作。
- 不迁移 SQLite/BlobStore，不引入 PostgreSQL、对象存储或任务队列。
- 不实现岗位研究、匹配、准备计划或完整 Parent Graph Web 流程。
- 不提供 OCR、DOCX 简历或代码仓库分析。

## 5. 验收标准

- Web API contract、上传边界和错误映射测试通过。
- 匿名 PDF fixture 能从 Web API 进入 Resume review。
- 全部 review 完成后可从 Web API 构建 CandidateProfile。
- 信息不足 fixture 可在 Web API 暴露 Candidate pending request，并通过回答恢复。
- 重复 response ID 不产生重复 Evidence、Claim 或 Snapshot。
- 前端 production build 通过，关键页面覆盖 loading、empty、review、interrupted、completed 和 error 状态。
- 现有全量 Python 回归通过；现有业务源文件无修改。
