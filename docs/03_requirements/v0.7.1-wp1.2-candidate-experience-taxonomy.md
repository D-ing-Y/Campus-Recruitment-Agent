# v0.7.1 WP1.2 Candidate 经历分类与 Tool Schema 补丁需求

状态：Accepted  
日期：2026-07-30  
前置：WP1、WP1.1、WP2 Passed

## 1. 当前问题

真实简历 `run-9c79eafe-789e-4500-9ef3-36aa3bfc5397` 已通过非思考 DeepSeek Tool
Calling 和外层 Pydantic 校验，但 21 个 claim candidate 中有 5 个被领域 Validator 拒绝：

- `experience.kind` 使用“项目经历”“科研经历”，而运行时只接受英文枚举；
- capability level 使用 `proficient`，而运行时只接受五级 canonical enum；
- `ExtractedClaim.value: Any` 使 Tool JSON Schema 没有把 predicate 对应的 value 枚举暴露给模型；
- 缺失 `experience.kind` 时 Projector 默认 `project`，会把科研经历误分为项目经历。

安全门禁工作正常，但画像完整性和分类准确性不足。

## 2. 调研结论

- MIT Career Services 将 jobs、internships、research、leadership、class projects、competitions、
  personal projects 都视为可用于招聘的 experience；其简历检查表还单列 Research Experience、
  Leadership & Service。
- Stanford Career Education 将 paid jobs、internships、volunteer/community service、
  academic/extracurricular teamwork or leadership projects、academic research/honors projects 都纳入
  Experience。
- Yale Career Strategy 将 academic work/class projects/research 与 internships、past employment、
  leadership positions 共同作为求职故事证据。
- Europass 区分 work、education/training、projects、volunteering、achievements，同时允许自定义
  section，说明简历输入属于开放世界，不能只依赖封闭枚举丢弃原文。
- 中国大学生在线的教育系统求职指导把校园/社会实践、学生工作、实习/工作、实习内项目分开；
  教育部资料还区分实习、就业见习、科研项目等经历。

因此不采用不断扩张的单轴 `kind`。采用：

```text
raw_label（原文，开放世界，必须保留）
    → kind（稳定大类，封闭枚举）
    → context（发生场景，封闭枚举，可为 unspecified/other）
```

## 3. 功能要求

### FR-01 稳定经历大类

`kind` 必须覆盖：

```text
employment | internship | research | project | competition | leadership |
campus_activity | volunteering | entrepreneurship | teaching | training | other
```

### FR-02 经历上下文

`context` 必须覆盖：

```text
employment | internship | coursework | capstone | thesis | academic_research |
public_funded_research | industry_collaboration | personal | open_source |
competition | campus | volunteering | entrepreneurship | training | community |
other | unspecified
```

分类示例：

| 简历内容 | kind | context |
| --- | --- | --- |
| 课程设计/课设 | project | coursework |
| 毕业设计 | project | capstone |
| 学位论文 | research 或 project | thesis |
| 实验室科研 | research | academic_research |
| 纵向课题 | research | public_funded_research |
| 横向/企业委托开发 | project 或 research | industry_collaboration |
| 实习岗位 | internship | internship |
| 实习中的独立项目 | project | internship |
| 工作岗位 | employment | employment |
| 工作中的交付项目 | project | employment |
| 个人项目 | project | personal |
| 开源贡献 | project | open_source |
| 学科竞赛 | competition | competition |
| 学生工作/社团 | leadership 或 campus_activity | campus |
| 志愿服务 | volunteering | volunteering 或 community |

### FR-03 开放世界保真

- `raw_label` 必须保留简历原始分类标签或最接近的原文短语；
- 无法规范化时使用 `kind=other`、`context=other|unspecified`，不得丢弃记录；
- `other` 必须携带非空 `raw_label`，供 inspect、人工纠正和后续 taxonomy 演进；
- 不得用 Projector 默认值把未知经历擅自改为 `project`。

### FR-04 Typed Tool Schema

LLM 输出使用以 `claim_kind` 为 discriminator 的 Pydantic union：

```text
capability | education | experience_kind | experience_text | experience_list | unsupported
```

- capability level 在 Tool JSON Schema 中暴露 canonical enum；
- capability id 在 Tool JSON Schema 中暴露当前 versioned ontology enum；
- experience kind/context 在 Tool JSON Schema 中暴露 canonical enum；
- education/text/list value 使用对应的 `str` / `list[str]`；
- 旧 predicate/value cache 与 fixture 只在解析边界迁移，不继续作为新 Prompt 输出格式。

### FR-05 双层校验

- Tool Schema/Pydantic 负责结构、枚举和基础类型；
- CandidateClaimValidator 继续负责 evidence owner/ref、ontology、predicate/value 联动和投影合法性；
- Tool Calling/Pydantic 通过不等于事实真实，领域 Validator 不得删除。

## 4. 非功能要求

- 不修改 WP2 CareerIntent 代码、状态和持久化契约；
- 旧 Candidate Claim、snapshot、cache 和 mock fixture 可回放；
- 新 schema/prompt 版本必须使旧 LLM cache 不被误当成新协议结果；
- 真实简历、raw Artifact、API key 不进入 Git；
- 新真实 smoke 必须证明 Tool Schema、Pydantic、领域 receipt 和 Profile 投影均通过。
