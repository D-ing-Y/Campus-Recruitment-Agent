## 1. 目的

本计划在实现前固定 v0.7.1 的数据层级、指标、失败场景和放行规则。实际测试结果不得回填到本计划
冒充设计；所有实际命令、时间、产物和限制写入后续 Eval report。

## 2. 验证层级

| 层级 | 名称 | 作用 | 能否证明真实可用 |
| --- | --- | --- | --- |
| E0 | schema/unit | 验证字段、纯函数和边界真值表 | 否 |
| E1 | repository/node | 验证副作用、单节点和事务 | 否 |
| E2 | offline subgraph | fixture 下验证 route/loop/checkpoint | 否，只证明离线结构 |
| E3 | CLI black-box | 已安装命令、任意 cwd、human/JSON/退出码 | 部分 |
| E4 | DeepSeek semantic smoke | 真实 provider 输出经 validator/projector | 只证明模型链 |
| E5 | live source smoke | 真实 recruitment/community search→detail、可选 official、auth/raw-first | 只证明当次来源链 |
| E6 | real-case vertical | 真实材料完成一个子 Workflow 九层 | 是，限该案例/时间 |
| E7 | connected workflow | Session 下跨图 handoff、恢复、重放 | 是，限 v0.7.1 应用服务范围 |

报告必须逐层陈述，禁止把 E0-E2 通过写成 E6/E7 通过。

## 3. 数据集

### 3.1 可提交数据

- 现有匿名/synthetic fixtures；
- Candidate predicate 错位的脱敏最小结构化 fixture；
- live raw 派生的、符合转载与隐私边界的最小脱敏 replay；
- failure injection fixtures。

### 3.2 本地 opt-in 数据

- 用户真实简历 PDF；
- 当前项目 README（可选，仅在用户已准备并明确选择时使用）；
- 用户真实求职意图；
- 用户显式授权的 DeepSeek 请求；
- 真实招聘 search/detail、社区 search/post-detail，以及按需 official raw；
- 用户登录产生的 credential ref。

本地数据、raw、Cookie、API key、完整 prompt/response 和可识别个人信息不得进入 Git。

## 12. Failure injection

至少覆盖：

- LLM timeout、invalid JSON、schema-valid/domain-invalid、retry/fallback；
- Blob raw write failure、SQLite transaction failure、checkpoint failure；
- Claim batch 中间项失败；
- duplicate material/response/event/handoff；
- stale Candidate/Intent/Role/Comparison/Plan；
- invalid owner/path/request/action/successor refs；
- auth required、rate limit、source changed、adapter required；
- Graph budget exhaustion 与用户 cancel；
- Run artifact writer 失败；
- 节点进程中断后恢复。

每个失败场景必须检查业务副作用、Run status、ErrorEvent、next action 和重试幂等。

## 13. 真实案例流程

```text
1. 创建 Session
2. 摄取真实简历 PDF；若用户已准备并选择项目 README，再作为可选证据追加
3. 用户确认发送 DeepSeek
4. 构建并人工复核 CandidateProfile
5. 创建并确认 CareerIntent
6. 使用真实来源研究成都 Agent/相关岗位
7. 构建 Job/Family Demand、Job/Company Reputation 与 RoleIntelligenceBundle
8. 运行 Matching 并选择目标
9. 创建 PreparationConstraints 并接受计划
10. 归档一条明确反馈
11. 确认高影响归因
12. 单步消费 handoff，产生 successor snapshot
13. rematch + replan
14. 检查 version chain、事件、报告和重复执行
```

真实来源若阻塞，可继续验收已完成层级，但 E5-E7 相关项目保持 blocked/partial，不伪造完整成功。

## 14. 放行规则

- WP0-WP6 每项必须先通过 E0-E3；涉及模型的 WP 再通过 E4；Role 再通过 E5。
- Candidate 未通过 E4，不进入基于该画像的最终 Matching 验收。
- Intent 未确认，不进入 Role live research。
- Role 无真实 detail 或合法 blocked 记录，不得声称 Role live 闭环。
- 没有 selected decision，不进入 Preparation。
- Feedback raw 未归档，不进入 interpretation。
- E7 未通过，不得称 v0.7.1 子图已连通。
- 只有实际 Eval report、全量回归和隐私检查完成后，版本才能从 Ready for Implementation 改为
  Implemented / Accepted。
