# v0.7.1 WP1.3 Structured Resume Evidence Eval 计划

状态：Ready  
日期：2026-07-31

## E0 Schema / Storage

- 八个标准区块、SourceRef、Review 和 Snapshot Pydantic 校验；
- Draft CAS、Receipt 幂等、Snapshot 不可变；
- 旧 Artifact、Claim、ProfileSnapshot 可读取。

## E1 Extraction

- pypdf 通过质量门禁时不调用 fallback；
- 低质量文本使用 pdfplumber；二者失败不生成 Draft；
- PII 本地提取，模型 messages/run artifacts 中 pii_leak_count=0；
- Tool 输出缺失值不猜测、引用只来自当前 PDF。

## E2 Review Graph

- 固定区块顺序；简单区块整块、列表区块逐条加 section-complete；
- confirm/correct/remove/retry/cancel、confirmed_empty；
- restart/resume、duplicate response、identity/request/revision 冲突；
- 全部确认前 snapshot_count=0、candidate_claim_count=0。

## E3 Candidate handoff / CLI

- confirmed Snapshot 可构建 Candidate；draft、取消、owner/candidate mismatch 被拒绝；
- Claim 同时追溯 Snapshot 与 Fragment；期望职位不进入 CandidateProfile；
- resume import/resume/show 与 candidate --resume-evidence；旧 --input 被拒绝；
- 旧 checkpoint 返回 legacy_session_incompatible。

## E4 Real resume

- 新 session/owner，真实带文本层 PDF，DeepSeek cache_hit=false；
- 用户按八个区块完成审核，修正结果与 PDF 一致；
- pre_confirmation_claim_count=0、unconfirmed_field_persisted_count=0、
  duplicate_review_write_count=0、pii_leak_count=0、traceability=100%；
- 使用新 CandidateSnapshot 重跑 WP2。真实正文、Prompt、PII 和 key 不进入 Git。

## Gate

定向测试、全量 pytest、compileall、git diff --check 和 E4 全部通过后，WP1.3 才可标记 Passed。
