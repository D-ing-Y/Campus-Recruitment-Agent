# v0.7.1 WP3.1 Eval Plan：岗位需求与评价画像分流

状态：Ready for Implementation
日期：2026-08-06

## 1. 目标

验证新 Workflow 同时解决两个问题：默认岗位闭环不再依赖逐公司官网 adapter；不同用途的社区证据不会
污染岗位要求、备考计划或岗位/公司评价。Eval 必须区分 contract、fixture、integration 与 live 证据层级。

## 3. Contract 与单元 Eval

### E1 招聘来源门禁

- search card + 无 detail：不得创建 Demand；
- recruitment detail + 完整 identity：允许创建 Demand；
- official 不可用：默认路径仍可完成；
- 关键字段跨平台冲突：创建 OfficialEscalationReceipt；
- 疑似关闭或用户显式要求：创建 escalation，但失败状态必须保留。

### E2 社区文档分类

覆盖 interview、employment、mixed、unknown：

- mixed 必须拆出独立 quote/Fragment；
- unknown、无详情、无 quote 和 scope ambiguous 不投影；
- LLM 输出非法 segment_type/usage 时 Validator 拒绝。

### E3 使用权限

- interview_question -> demand_assessment：接受；
- interview_question -> reputation：拒绝；
- work_intensity -> reputation_job/company：按 scope 接受；
- work_intensity -> Demand/Preparation requirement：拒绝；
- company-only evidence -> JobReputationProfile：拒绝。

### E4 聚合语义

- 单篇评价只标记 insufficient_sample/observed；
- 多个同向独立来源可以提升 sample status；
- 相反评价保留 disputed 与双方引用；
- 公司聚合保留不同 role family 的样本分布；
- 任何输出均不存在 overall score。

## 4. Graph 与恢复 Eval

- 多 SearchScope 分别建立 CompanyRoleGroup，不跨 scope 污染；
- recruitment 和 community 预算分别耗尽时保留各自阶段状态；
- community 被阻断时允许发布 Demand，并在 Bundle 标记 Reputation 缺失；
- Demand 缺少平台 detail 时不得用社区内容代替；
- 重复运行、重复详情和重复 resume response 零重复写入；
- 旧 RoleProfileSnapshot 可读，新 run 不回写旧 `hiring_signals`。

## 5. Consumer Isolation Eval

- Matching 输入只含 accepted Demand requirement IDs；
- Preparation 输入只含 requirement 和 assessment signal IDs；
- Reputation 的 work intensity、atmosphere、compensation 等 ID 不进入能力 Gap 或学习 Activity；
- TargetDecision 与 Role Q&A 可以读取 Reputation，但输出标注来源类型；
- consumer 收到越界 ID 时返回 `evidence_usage_violation`。

## 6. Fixture 场景

至少覆盖：

1. 单公司单岗位 + 招聘详情 + 面经；
2. 单公司多个相似岗位 + 公司级评价；
3. 单篇 mixed 帖子同时包含面试和入职体验；
4. 平台之间职责或地点冲突；
5. 只有 search card、没有 detail；
6. 社区搜索命中但详情需要登录；
7. 多篇评价对工作强度结论冲突；
8. generic family 面经与 company-role 面经同时存在。

## 7. 受控 Live Eval

### L1 招聘平台闭环

使用至少一个真实启用 adapter 完成：

`SearchScope -> search Raw -> platform job-detail Raw -> JobDemandProfile`

记录 source、artifact/document/profile ID、安全统计和失败码；不提交完整 JD 或个人化查询正文。

### L2 社区闭环

使用至少一个真实启用 adapter 完成：

`CompanyRoleGroup -> community search Raw -> post-detail Raw -> typed segment -> profile`

至少各验证一条 interview 和 employment segment；若来源受登录、风控或空结果限制，状态为 blocked/partial，
不得用 fixture 替代 live accepted。

## 8. WP3.1 完成条件

- 所有核心指标通过；
- 聚焦与全量回归通过；
- L1 和 L2 均有真实 detail Raw Artifact 与投影追溯；
- 版本矩阵明确区分 offline fixture 与 authenticated/live 结果；
- Demand、Reputation、Bundle 的当前对象 ID 和安全统计写入执行日志；
- 未满足时 WP3.1 保持 `Ready for Implementation`、`In Progress` 或 `Blocked`，不得标记完成。
