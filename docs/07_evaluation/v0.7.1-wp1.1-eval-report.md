## 4. 真实 DeepSeek 失败与修复

- 首次重构后简历运行 `run-d64a0a09-69cd-4460-b225-b84cd1badd1c` 失败：Provider
  返回 HTTP 400。
- 无业务数据最小复现确认原因：DeepSeek Thinking 默认开启，但 Pydantic ToolStrategy
  使用强制 `tool_choice`，当前 endpoint 拒绝该组合。
- Provider adapter 现在依 capability 对 structured call 注入
  `extra_body={"thinking":{"type":"disabled"}}`；相同最小 schema 返回 Pydantic 对象。
- 该结论与 DeepSeek 官方 Thinking Mode 文档一致：Thinking 默认 enabled，OpenAI 格式通过
  `extra_body.thinking` 切换。

## 5. Tool 与 MCP

- 旧 Tool 无 `ToolSpec` 时不对模型可见。
- `ToolSpec` 的 Pydantic args schema 在原 Tool 执行前校验；write/model_action 无确认时拒绝注册。
- 模型协议名使用单独 `wire_name`，避免内部 dotted name 违反 Provider Tool 命名约束。
- stdio FastMCP fixture 的 `add` 能加载和调用，`subtract` 未在 allowlist 中不暴露。
- 空 allowlist 拒绝全部；本地/MCP 重名失败；单个不可达 server 生成脱敏
  `external_dependency` diagnostic，不阻断其他 server。
