## 2. 发现并修复的问题

1. validation receipt 的持久化主键曾被错取为 `draft_id`，与 draft 发生冲突；现按每种记录的
   显式 ID 选取主键。
2. LangGraph 的 trace/LLM/error list 未定义 reducer，跨 interrupt/resume 可丢失历史；现使用
   append reducer。
3. 多个同 key 偏好在 revision 时可相互覆盖；现稳定聚合并去重。
4. 真实 DeepSeek 曾将“互联网科技公司”标为 `industry`，并将校招类型标为 negotiable。
   Tool Calling 只保证结构，不保证业务语义；现由确定性 policy 将“…公司”类偏好归一为
   `company_type`，并校正 hard/negotiable 边界。
5. revision 曾将未修改 constraint 的 `source_ref` 也重写到 response patch；现仅被修改字段
   引用 response fragment，其他字段继续引用原始 intent fragment。
6. Graph 曾只检查 session 中的 Candidate ref，未交叉检查实际 Profile owner/type；现在模型调用前
   验证 snapshot 存在、类型和 owner。
7. 失败 run 曾将所有模型错误压平为 `internal_error`，未确认阶段也曾将 projection 指标写成
   1.0；现保留失败 LLM receipt 并区分 unavailable/invalid output，未评估指标返回 null。
