## 2. 修复的问题

1. 新旧简历和不同解析版本的 active Claim 曾被同时投影，产生 Python 等级、SQL 元数据和毕业时间
   粒度伪冲突；现在由确定性 resolution 按当前 Resume basis 选择。
2. capability 说明元数据、experience 原标签、NFKC/空白差异和同年 `YYYY`/`YYYY-MM` 曾被误判为
   不同事实；现在分别按 canonical level、kind/context、归一字符串和日期 refinement 比较。
3. 一次 correction 曾为每条 predecessor 各建一条重复 successor；现在只建一条 successor，并在
   SQLite 单事务内 supersede 全部目标 Claim。
4. Feedback rebuild 曾再次读取全部 active Claim；现在与 Candidate build 共用同一 resolution。
5. Candidate 最终投影漏传 `resume_evidence_id`，可出现 completed 同时带 fatal error；现完成态必须
   使用相同 evidence basis，最终投影失败会真实标记 failed，cancel 不再额外投影。
6. 已注册 immutable Snapshot 在新 Session 复用时曾因 session-local predecessor 不同触发 identity
   conflict；现在 ObjectRef 以 type、owner、schema 与 canonical hash 校验真实身份。
7. failed session、已恢复且仅有 ResumeEvidence 的 session、Candidate pending request 现在分别返回
   `session.resume`、`candidate.build`、`candidate.resume`。
